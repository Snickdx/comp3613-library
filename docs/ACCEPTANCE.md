# Library Workshops — public acceptance criteria

Derived from elicitable stakeholder needs (Phase 1). Instructor private defects are **not** listed here.

## Roles

1. Lecturers can submit workshop booking requests online (course code, headcount, date, resources).
2. A library coordinator manages availability, capacity, and conflict outcomes.
3. Admins may support coordinator operations where appropriate.

## Booking content

4. Incomplete requests (missing course code, date, resources, or non-positive headcount) are rejected with clear feedback.
5. An accepted booking produces a shareable confirmation a lecturer can show students.
6. Lecturers can cancel their booking when a class is moved; cancelled bookings must not remain usable as confirmations or keep blocking the slot incorrectly.

## Conflict & capacity

7. Rooms must never be silently overbooked beyond capacity (default **30** when a room has no override).
8. When two classes request the same room+date slot, the **earlier** request wins unless the coordinator explicitly overrides for a **larger** cohort.
9. Conflict resolution records which request was accepted and whether an override occurred.

## Trust

10. Passwords are stored hashed; login responses never include password material.
